Retries and failures

When a job raises an exception, Queuetopia records the traceback and schedules a retry. The delay grows exponentially: 10 seconds, 40 seconds, 160 seconds and so on. After the last retry the job moves to the failed state.

The default is 5 retries. Set retries on the decorator to change it, for example @job(queue="email", retries=3). Jobs that should never retry can set retries=0.

Retry failed jobs from the command line with queuetopia retry --queue email --state failed.

Jobs that call external APIs should be idempotent, because a worker can crash after the API call and before it marks the job done.
